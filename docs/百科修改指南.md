# 暗黑2百科 · 修改指南

**适用对象：shu 模组（也可用于其他 D2R 模组）**
**整理日期：2026-10-27**

---

## 一、先搞清楚：百科文字存在哪两层

**很多人卡住的原因，是把「面板」和「文字」当成一个东西。实际上它们分属两个文件：**

```
第 1 层  面板结构
         Data\global\ui\layouts\runewordspanelhd.json
         · 有哪些条目
         · 每条用哪几个符文图标
         · 每条指向哪个文字键

第 2 层  文字内容
         Data\Local\Lng\Strings\npcs.json
         · 标题行
         · 详细属性
         · 评语与底材推荐
```

**面板文件本身**不含任何可读文字，只有 `@键名` 的引用。真正的文字全在 `npcs.json`。

---

## 二、改一条百科文字的五个步骤

### ① 在面板文件里定位条目

**在 `runewordspanelhd.json` 里搜索 `RuneWord` 加条目名，例如「谜团」：**

```json
"name": "ArmorRuneWordEnigma"
```

**命名规律：`<护甲类型>RuneWord<英文名>`，前缀有四种：**

```
HelmetRuneWord...   头盔类
ArmorRuneWord...    护甲类
ShieldRuneWord...   盾牌类
WeaponRuneWord...   武器类
```

### ② 看它绑定了哪些文字键

**同一个 widget 块里有两个 `text` 字段：**

```json
"name": "RuneWordText",
"fields": {
  "text": "@jghelp50337runewordEnigma"        ← 标题（面板列表里显示的那一行）
}
```

**悬停时展开的大段文字来自相邻的 widget：**

```json
"text": "@jghelp50337runewordtooltipEnigma"   ← 详细内容
```

**规律：详情键 = 标题键 + `tooltip`。**

### ③ 到 npcs.json 里搜这个键

```json
{
  "id": 50337,
  "Key": "jghelp50337runewordtooltipEnigma",
  "enUS": "",
  "zhTW": "ÿc4\n護甲\nÿc3+2 所有技能\n...",
  "zhCN": "ÿc4\n护甲\nÿc3+2 所有技能\n..."
}
```

**只改 `zhCN` 就够；想同步繁体再改 `zhTW`。**

### ④ 按格式改写文字

**标准结构（颜色代码见第三节）：**

```
ÿc4
<适用装备>
ÿc3<属性行 1>
<属性行 2>
...
（空行）
ÿcP重要属性:...
其它亮点:...
美中不足:...
（空行）
ÿc;心得评语...
ÿc2底材推荐
ÿc8<底材名>
<推荐理由>
适用CHAR:...
```

### ⑤ 存盘，重启游戏

**`npcs.json` 属于本地化文件，**不走 BIN 编译流程**，改完直接生效。**

**这一点和 `excel\*.txt` 完全不同 —— 后者必须重新编译 BIN。**

## 三、颜色代码速查

**`ÿc` 是调色指令，后面跟一个字符：**

| 代码 | 颜色 | 常见用途 |
| --- | --- | --- |
| `ÿc0` | 白 | 普通文字 |
| `ÿc1` | 浅灰 | 「(变动)」这类标记 |
| `ÿc2` | 蓝 | 技能名、光环名 |
| `ÿc3` | 黄 | 属性列表主体 |
| `ÿc4` | 金 | 标题 |
| `ÿc8` | 绿 | 底材名 |
| `ÿcP` | 紫 | 重要属性 / 其它亮点 |
| `ÿc;` | 黄绿 | 心得评语 |

**换行用 `\n`。**

**颜色是**有状态**的 —— 设了 `ÿc3` 之后，后面的行都会保持黄色，直到下一次调色。**

**所以属性行里凡出现 `ÿc1(变动)ÿc3`，是为了「临时变灰、再变回黄」。**

---

## 四、🔴 最容易踩的坑：JSON 转义

**在 `.json` 文件里，换行必须是 `\n`（反斜杠 + 字母 n，共两个字符），**不能是真换行**。**

**写错的效果：整个文件变成非法 JSON，游戏加载时直接报错或黑屏。**

**判断方法：改完之后用任意工具解析一次，能通过就说明没写坏。**

**另外，文字里的双引号要写成 `\"`。**

## 五、属性行的数据从哪来

**一条符文之语的完整属性 = **两部分相加**，缺一不可。**

### 1. 符文之语自身属性

**来源：`Data\global\excel\runes.txt`**

**七组槽位，每组四个字段：**

```
T1Code1  T1Param1  T1Min1  T1Max1
T1Code2  T1Param2  T1Min2  T1Max2
...
T1Code7  T1Param7  T1Min7  T1Max7
```

**`T1Min` ≠ `T1Max` 时，显示为 `最小值-最大值`，并加「(变动)」。**

### 2. 符文自带属性

**来源：`Data\global\excel\gems.txt`（一般是原版，mod 里可能没有这个文件）**

**每个符文有三组武器属性：**

```
weaponMod1Code  weaponMod1Param  weaponMod1Min  weaponMod1Max
weaponMod2...
weaponMod3...
```

**按构成符文逐个累加。同代码的累加值求和。**

### 举例：无限 Infinity

**符文：Ber(30) + Mal(23) + Ber(30) + Ist(24)**

**符文之语自身给（7 条）：**

```
dmg%        255-325      → +255-325% 强化伤害
move3       35-45        → +35-45% 更快速跑步/步行
vit/lvl     4            → +(0.5-49.5) 活力 (基于角色等级)
aura        Conviction   → 装备时获得 17-20 级定罪光环
kill-skill  ChainLight   → 50% 几率消灭敌人时施放 20 级连锁闪电
pierce-ltng 45-55        → -45-55% 敌人的闪电抗性
pierce-fire 45-55        → -45-55% 敌人的火焰抗性
```

**符文自带给（3 条）：**

```
Ber ×2  → crush 20 + 20 = +40% 几率粉碎打击
Mal     → noheal         = 防止怪物治愈
Ist     → mag% 30        = 30% 额外几率获得魔法物品
```

**合计 10 条 —— 这才是游戏里那把无限真正显示的属性。**

## 六、常见问题排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 改了文字但游戏里没变 | 改错了键，或改的是 `enUS` | 确认改的是 `zhCN`，并确认键名与面板里的 `@` 引用一致 |
| 游戏加载失败 / 黑屏 | JSON 写法坏了（真换行、引号未转义、逗号多余） | 从备份还原，重新写 |
| 颜色显示成 `ÿc3` 字样 | `ÿ` 字符编码损坏 | 确认文件是 UTF-8，且 `ÿ` 是单字符不是转义 |
| 文字挤在一起 | 少了 `\n` | 每行之间补 `\n` |
| 面板里找不到某条 | 该符文之语未被收录 | 需要新建 widget，不是改文字能解决的 |
| 符文图标数量不对 | 面板里固定 3~6 个位置 | 图标引用是 `$FileRune<N>`，`<N>` 即 `rNN` 的编号 |

## 七、备份与还原

**改之前一定先复制一份原文件：**

```
npcs.json          →  npcs.json.bak_日期
runewordspanelhd.json  →  runewordspanelhd.json.bak_日期
```

**出问题直接改回名字即可，不需要重新下载模组。**

---

## 八、一句话总结

**面板管「显示什么」，`npcs.json` 管「显示成什么字」，`runes.txt` + `gems.txt` 管「应该显示什么」。**

**三者对齐，百科才不会骗人。**
